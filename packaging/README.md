# Packaging Files for NeoWall

This directory contains files needed by package maintainers.

## What's Here

- **`PKGBUILD`** - Canonical Arch `neowall-git` recipe (auto-published to the AUR)
- **`systemd/neowall.service`** - Systemd user service file
- **`neowall.install`** - Optional Arch Linux post-install script
- **`neowall.desktop`**, **`neowall.svg`** - Desktop entry and icon

## For Package Maintainers

If you're packaging NeoWall for a distribution, see:
- **[docs/PACKAGING.md](../docs/PACKAGING.md)** - Complete packaging guide

### Quick Reference

**Build:**
```bash
meson setup build --prefix=/usr
ninja -C build
DESTDIR="$pkgdir" ninja -C build install
```

**Systemd service install location:**
```
/usr/lib/systemd/user/neowall.service
```

**Arch .install file usage:**
Add to PKGBUILD:
```bash
install=neowall.install
```

## Creating AUR Package

The canonical `neowall-git` PKGBUILD **is** kept in this repo, at
`packaging/PKGBUILD`, and CI pushes it to the AUR verbatim on every release
(see `.github/workflows/release.yml`, job `publish-aur`). `neowall-bin` is
generated by that same job from the release artifacts.

Edit `packaging/PKGBUILD` here — **not** on the AUR. A manual AUR edit will be
overwritten by the next release.

Do not hand-edit `pkgver` either; it is derived from `meson.build`:

```bash
scripts/version.sh set 0.5.3   # rewrites meson.build, flake.nix and PKGBUILD
scripts/version.sh check       # CI runs this on every push
```

See [docs/PACKAGING.md](../docs/PACKAGING.md) for the full release runbook.

## Notes

- `packaging/PKGBUILD` is the Arch source of truth and is auto-published.
- `.deb` / `.rpm` / AppImage are produced by CI with `fpm`; there are no
  per-distro spec files to maintain.
- A daily workflow (`packaging-freshness.yml`) files an issue if any published
  package falls behind the latest release.
